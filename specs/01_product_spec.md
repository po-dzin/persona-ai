# 01 · Product Spec (MVP + Phase 1)

## 1) Product goal

Проверить платёжеспособный спрос на анимацию портретных фото в Telegram и web-канале с понятной экономикой пакетов.

Ключевой JTBD:

- Пользователь быстро получает эмоциональный результат (живое фото).
- Первый опыт максимально простой: 1 free generation без оплаты.
- После value-moment — понятный переход к пакетам.

## 2) Scope

### MVP (обязательно)

- Авторизация через Telegram (Mini App) и Telegram Login/OAuth (Web).
- Загрузка фото (JPG/PNG, до 10 MB).
- Выбор стиля с превью.
- 1 бесплатная генерация на нового пользователя.
- Пакеты генераций (Stars/Stripe).
- Экран прогресса с этапами и ETA-range.
- Экран результата (play/download/share).
- История генераций (галерея).
- Базовый профиль (имя, username, аватар, баланс генераций).

### Phase 1.1

- Подарочные пакеты.
- Партнерская программа (реферальные коды, dashboard).
- A/B тарифов и trial-механики.

## 3) Business model

- Unit = 1 generation credit.
- Trial: `free_credits = 1` (one-time).
- Продажи: 3 пакета `S/M/L` = `5 / 20 / 50` кредитов.
- Цена пакета строится от базовой себестоимости генерации с мультипликатором `x2..x3`.
- Цена за 1 кредит снижается при росте пакета: `S > M > L`.

## 4) User journey

1. Onboarding: показываем before/after пример и ограничения.
2. Upload: пользователь загружает фото.
3. Style pick: выбирает стиль по gif/video-превью.
4. Credit check:
- Если есть free/paid credit → запускаем генерацию.
- Если кредитов нет → paywall с пакетами.
5. Processing: статус по этапам + ETA-range.
6. Result: видео + CTA `Share`, `Try another style`.
7. History/Profile: доступ к прошлым генерациям и остаткам.

## 5) Key product rules

- Один пользователь получает free-кредит только один раз.
- Один заказ = одна списанная единица кредита.
- При техническом фейле кредит возвращается автоматически.
- Контент-нарушение (policy fail) кредит не возвращается по умолчанию; ручной override через support.

## 6) Policy & trust

- Запрещённый контент: NSFW, чужие фото без согласия, знаменитости/публичные лица (MVP policy).
- Прозрачность: “результат может немного отличаться от превью”.
- SLA-copy: “обычно 40–180 секунд” (единое обещание для всех поверхностей).
- Privacy baseline: удаление source photo по TTL, result по политике хранения.

## 7) MVP success criteria

- Free→paid conversion: не ниже целевого порога команды.
- p95 end-to-end completion time: в целевом SLA.
- Технический failure rate: в допустимом пороге.
- Повторные генерации в первые 7 дней: рост неделя к неделе.
